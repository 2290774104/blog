# RESTful API

`RESTful API` 是一种基于 **REST（Representational State Transfer，表述性状态转移）** 架构风格设计的 Web API。它利用 HTTP 协议的标准方法，以简洁、统一的方式对资源进行操作。

## 接口请求方法

通常情况下，接口请求方法如下：

| 方法   | 语义     | 示例            | 说明         |
| ------ | -------- | --------------- | ------------ |
| GET    | 查询     | GET /users      | 获取资源列表 |
| GET    | 查询     | GET /users/1    | 获取单个资源 |
| POST   | 创建     | POST /users     | 新建资源     |
| PUT    | 全量更新 | PUT /users/1    | 替换整个资源 |
| PATCH  | 部分更新 | PATCH /users/1  | 更新部分字段 |
| DELETE | 删除     | DELETE /users/1 | 删除资源     |

- `GET`方法用于查询资源
- `POST`方法用于创建资源
- `PUT`方法用于全量更新资源
- `PATCH`方法用于部分更新资源
- `DELETE`方法用于删除资源

## 请求参数

- 查询参数：在 URL 后面的参数，用于指定查询条件。
- 路径参数：在 URL 中的参数，用于指定资源的唯一标识符。
- 请求体：在请求体中的参数，用于传递创建或更新资源的详细信息。
- 请求头：在请求头中的参数，用于传递请求的元信息，如认证信息、内容类型等。

## 响应参数

- 响应体：在响应体中的参数，用于传递操作结果或资源的详细信息。
- 响应头：在响应头中的参数，用于传递响应的元信息，如状态码、内容类型等。

目前常用的响应体格式有 JSON、XML 等。

这里以 JSON 格式为例。

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "id": 1,
    "name": "张三",
    "age": 18
  }
}
```

### 状态码

| 状态码 | 含义               |
| ------ | ------------------ |
| 200    | 成功               |
| 201    | 创建成功           |
| 204    | 删除成功（无内容） |
| 400    | 请求参数错误       |
| 401    | 未认证             |
| 403    | 无权限             |
| 404    | 资源不存在         |
| 500    | 服务器错误         |
