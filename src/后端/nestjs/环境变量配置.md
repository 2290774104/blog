# 环境变量配置

项目在开发、测试、生产等不同环境下，数据库地址、密钥、端口等配置往往不同。把这些易变的配置抽离成环境变量，可以避免将敏感信息硬编码到代码中，也方便在不同环境之间切换。

## 安装依赖

```sh
pnpm add @nestjs/config js-yaml lodash-es
pnpm add -D cross-env @types/js-yaml @types/lodash-es
```

- `@nestjs/config`：`Nest` 官方的配置模块，负责加载和读取环境变量
- `js-yaml`：解析 `yaml` 格式的配置文件
- `cross-env`：跨平台设置环境变量，解决 `Windows` 与 `Linux/Mac` 语法不一致的问题
- `lodash-es`：提供 `lodash` 的 `es-module` 版本，这样用于合并配置项

## cross-env 与启动脚本

不同系统设置环境变量的语法不同，`Linux/Mac` 使用 `NODE_ENV=development`，而 `Windows` 的 `cmd` 使用 `set`，`PowerShell` 使用 `$env:`。`cross-env` 统一了写法，保证脚本在各平台都能执行。

在 `package.json` 中配置启动脚本：

```json
{
  "scripts": {
    "start:dev": "cross-env NODE_ENV=development nest start --watch",
    "start:prod": "cross-env NODE_ENV=production node dist/main"
  }
}
```

执行 `pnpm start:dev` 时，`process.env.NODE_ENV` 会被设置为 `development`，后续就可以根据它加载不同的配置文件。

## 使用 @nestjs/config

在根模块中注册 `ConfigModule`，`isGlobal: true` 表示全局可用，无需在每个模块重复导入。

::: info app.module.ts
:::

```ts
import { Module } from '@nestjs/common';
import { ConfigModule } from '@nestjs/config';

@Module({
  imports: [
    ConfigModule.forRoot({
      isGlobal: true,
      envFilePath: [`.env.${process.env.NODE_ENV}`, '.env'],
    }),
  ],
})
export class AppModule {}
```

- `envFilePath`：按数组顺序查找，先找到的优先，未找到的继续往下找
- `ignoreEnvFile`：设为 `true` 时忽略 `.env` 文件，仅使用系统环境变量，常用于生产环境
- `cache`：设为 `true` 时缓存配置，提升读取性能

## .env 文件

在项目根目录新建 `.env` 文件：

```ini
# .env
PORT=3000
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=123456
```

不同环境使用不同的文件，如 `.env.development`、`.env.production`，并通过上面的 `envFilePath` 按环境加载。`.env` 文件包含敏感信息，需要加入 `.gitignore`，通常只提交一份 `.env.example` 作为模板。

## 读取配置

在需要的地方注入 `ConfigService` 读取配置：

```ts
import { Injectable } from '@nestjs/common';
import { ConfigService } from '@nestjs/config';

@Injectable()
export class AppService {
  constructor(private readonly configService: ConfigService) {}

  getPort(): number {
    // 第二个参数为默认值
    return this.configService.get<number>('PORT', 3000);
  }

  getDbConfig() {
    return {
      host: this.configService.get<string>('DB_HOST'),
      port: this.configService.get<number>('DB_PORT'),
      user: this.configService.get<string>('DB_USER'),
      password: this.configService.get<string>('DB_PASSWORD'),
    };
  }
}
```

也可以在 `main.ts` 中通过 `app.get()` 获取：

```ts
import { NestFactory } from '@nestjs/core';
import { ConfigService } from '@nestjs/config';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  const configService = app.get(ConfigService);
  const port = configService.get<number>('PORT', 3000);

  await app.listen(port);
}
bootstrap();
```

## 使用 js-yaml 加载 yaml 配置

当配置项较多、存在层级结构时，`yaml` 比 `.env` 更清晰。借助 `@nestjs/config` 的 `load` 选项和 `js-yaml`，可以自定义配置加载逻辑。

新建配置文件：

```yaml
# config/config.yaml
db:
  host: localhost
  port: 3306
  username: root
  password: 123456
  database: nest_template
```

```yaml
# config/config.development.yaml
db:
  database: nest_template_development
```

```yaml
# config/config.production.yaml
db:
  database: nest_template_production
```

编写配置工厂，根据 `NODE_ENV` 读取对应的 `yaml` 文件：

::: info src/configuration.ts
:::

```ts
import { readFileSync } from 'fs';
import * as yaml from 'js-yaml';
import { dirname, join } from 'path';
import { fileURLToPath } from 'url';
import { merge } from 'lodash-es';

const YAML_CONFIG_FILE = 'config.yml';
const filePath = join(
  dirname(fileURLToPath(import.meta.url)),
  '../config',
  YAML_CONFIG_FILE,
);
const envPath = join(
  dirname(fileURLToPath(import.meta.url)),
  '../config',
  `config.${process.env.NODE_ENV ?? 'development'}.yml`,
);

const commonConfig = yaml.load(readFileSync(filePath, 'utf-8')) as Record<
  string,
  unknown
>;
const envConfig = yaml.load(readFileSync(envPath, 'utf-8')) as Record<
  string,
  unknown
>;

export default () => {
  return merge(commonConfig, envConfig);
};
```

在 `ConfigModule` 中注册：

```ts
import { Module } from '@nestjs/common';
import { ConfigModule } from '@nestjs/config';
import Configuration from './configuration';

@Module({
  imports: [
    ConfigModule.forRoot({
      isGlobal: true,
      load: [Configuration],
    }),
  ],
})
export class AppModule {}
```

读取嵌套配置时使用点号路径：

```ts
const port = this.configService.get<number>('app.port');
const dbHost = this.configService.get<string>('db.host');
```

::: tip
`yaml` 中读取的值不会经过 `dotenv` 的类型转换，`port: 3000` 本身就是数字类型，无需再转换；而 `.env` 中的值都是字符串，`get<number>()` 只是类型断言，实际仍是字符串，需要转换时应使用 `parseInt` 或 `ValidationPipe`。
:::
